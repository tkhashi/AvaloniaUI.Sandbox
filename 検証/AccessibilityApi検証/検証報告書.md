# Accessibility API 検証報告書

## 1. 概要
本検証は、macOS 上で AvaloniaUI (.NET 10) アプリから以下を取得できるかを確認することを目的とした。

- 現在開いているウィンドウ一覧（アプリ名 / 左上座標 / PID）
- 一覧から選択したウィンドウの AX 要素（操作可能要素）の階層

結論として、要件の主機能は達成できた。

## 2. 実装技術
- ランタイム/フレームワーク: .NET 10, AvaloniaUI 11
- OS: macOS
- ネイティブ連携: P/Invoke（ApplicationServices.framework / CoreFoundation.framework）

主に利用した API:

- ウィンドウ一覧取得: `CGWindowListCopyWindowInfo`
- AX 要素取得: `AXUIElementCreateApplication`, `AXUIElementCopyAttributeValue`, `AXUIElementCopyActionNames`
- 型変換/参照管理: `CFString*`, `CFArray*`, `CFDictionary*`, `CFNumber*`, `CFRelease`, `CFRetain`

## 3. 取得ロジック
### 3.1 ウィンドウ一覧
1. `CGWindowListCopyWindowInfo` で画面上ウィンドウ情報を取得
2. `kCGWindowLayer == 0` を対象に絞り込み
3. `kCGWindowOwnerName`（アプリ名）, `kCGWindowName`（ウィンドウタイトル）, `kCGWindowOwnerPID`（PID）, `kCGWindowBounds.X/Y`（左上座標）を抽出
4. 重複除去・ソートして一覧表示

### 3.2 AX 要素一覧
1. 選択ウィンドウの PID から `AXUIElementCreateApplication` を作成
2. 通信ハング対策として `AXUIElementSetMessagingTimeout` を設定
3. `AXWindows` から対象ウィンドウを特定（不一致時は `AXFocusedWindow` → 先頭ウィンドウへフォールバック）
4. `AXChildren` を幅優先探索して階層列挙
5. 各要素から `AXRole`, `AXSubrole`, `AXTitle`（なければ `AXDescription`）, `AXActions`, `AXPosition`, `AXSize` を取得

## 4. 取得できた情報
- ウィンドウ単位
  - アプリ名
  - ウィンドウタイトル
  - PID
  - 左上座標 (X, Y)
- AX 要素単位
  - 階層（Depth）
  - Role
  - Subrole
  - Title / Description
  - Actions
  - Position (X, Y)
  - Size (Width, Height)

## 5. 取得できなかった/制約がある情報
- アプリ・要素によっては `AXPosition` / `AXSize` / `AXTitle` / `AXActions` が未提供で、`(なし)` になる
- 選択ウィンドウ同定は「タイトル + 座標」ベースのため、同一タイトル・近似座標が複数ある場合はフォールバック選択が入る
- AX 要素取得は macOS のアクセシビリティ許可が前提（未許可時は取得不可）
- セキュリティ上保護された UI（例: パスワード内容など）は値を取得できない、またはマスクされる場合がある

## 6. 安定化対応（検証中に実施）
- AX 全プロセス走査による停止を回避するため、ウィンドウ一覧は WindowServer API へ変更
- AX 通信タイムアウト導入
- CoreFoundation 参照寿命（`CFRetain`/`CFRelease`）の見直し
- UI 側で AX 取得待機タイムアウトを導入
- ログ出力（`accessibility-api.log`）で取得進行を追跡可能化

## 7. 結論
- 要件で求められた「ウィンドウ一覧取得」と「選択ウィンドウの AX 要素一覧取得」は達成
- 追加で AX 要素の座標・サイズも取得可能であることを確認
- 未取得項目は主に対象アプリ側の AX 属性公開有無および macOS のセキュリティ制約に起因
